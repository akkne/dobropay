# Документация Dobropay

Перед изменением проекта прочитай [корневой README](../README.md), затем [актуальное архитектурное задание](architecture/architecture.md). Оно задаёт целевую структуру из отдельных сервисов и локальный сценарий через Kafka. Прямое указание владельца репозитория размещать серверный код в `backend/` имеет приоритет над примером пути `src/` в задании.

| Документ | Назначение |
| --- | --- |
| [Git-процесс](git-process.md) | Обязательные правила веток, коммитов, push и проверок для агентов. |
| [Архитектурное задание](architecture/architecture.md) | Целевые сервисы, БД, Kafka, Redis и критерии приёмки. |
| [API](api.md) | Публичный контракт платежей и webhook. |
| [Локальная разработка](local-development.md) | Запуск, миграции и проверка доступа. |
| [Runbook](runbook.md) | Диагностика платежей и доставок. |
| [Roadmap](roadmap.md) | Следующие этапы и открытые продуктовые решения. |
| [ADR](adr/) | Краткие записи о принятых решениях. |

Документы с описанием фактической реализации обновляются вместе с изменениями кода. Пока переход на новую архитектуру не завершён, статус работающего контура указан в корневом README.
