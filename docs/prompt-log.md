# Журнал запросов по проекту

Документ составлен по локальному файлу `ai-requests.json`. В заметке к источнику указано, что это сокращённая редакция ранних запросов и реконструкция недоступных записей по дорожной карте и истории Git. Поэтому формулировки ниже передают содержание записей, но не считаются дословной стенограммой. Они описывают историю проекта и не являются актуальными инструкциями для выполнения работ.

## Начальная настройка и сквозной сценарий

1. Создать Dobropay на .NET 10 и подготовить локальный сценарий: создание платежа, гостевой checkout и просмотр подписанного webhook.
2. Использовать Code First и миграции EF Core для базы данных.
3. Оставить полезные модульные и интеграционные тесты; полный прогон выполнять после фичи и перед pull request.
4. Делать небольшие коммиты по одной микрофиче, применять Conventional Commits и проверять индекс перед коммитом.
5. Зафиксировать правила Git в документации и добавить ссылку на них в `AGENTS.md`.
6. Заполнить `README.md` и `AGENTS.md`, держать серверный код в `backend/` и осматривать соседние каталоги перед изменениями.
7. Перейти к отдельным микросервисам по архитектурному документу и добавить версионирование API и событий Kafka.
8. Вести простой JSON-журнал запросов к агентам, исключить его из Git и восстановить доступную историю работы над проектом.

## Как читать журнал

Пункты отражают направление работ, а не подтверждают, что каждая функция в итоге реализована или доступна пользователю. Текущее состояние следует проверять по исходному коду, [README проекта](../README.md), [документации API](api.md) и [дорожной карте](roadmap.md). Например, более ранние запросы описывают криптопровайдера, а более поздний запрос ограничивает доступные способы оплаты картой и СБП.
