# Правила проекта

- Сначала прочитай корневой `README.md`, затем `docs/README.md` и актуальное ТЗ `docs/architecture/architecture.md`. Прямые указания пользователя имеют приоритет над путями в документах: серверный код находится в `backend/`.
- **Перед проектированием или правкой осмотри весь репозиторий:** `git status --short --branch`, дерево `backend/`, `frontend/`, `docs/`, `tests/`, инфраструктурные файлы, решение и существующие контракты. Проверь также staged, unstaged и новые файлы. Не выбирай новую структуру по одному файлу и не игнорируй соседние папки.
- Текущая целевая архитектура — отдельные сервисы, а не модульный монолит. У каждого сервиса свой проект, процесс, настройки и владелец данных. Разделяй код по понятным каталогам внутри сервиса; дополнительные папки допустимы, когда они делают ответственность яснее.
- **Перед любой работой с Git обязательно прочитай `docs/git-process.md` целиком и строго следуй ему.** Работай в ветке фичи, делай небольшие Conventional Commits и пушь каждый коммит согласно этому документу. Автор и коммиттер — владелец репозитория; не добавляй трейлеры соавторства или подписи инструментов.
- Сохраняй существующие изменения рабочего дерева и индекса. В свой коммит добавляй только файлы задачи; перед коммитом проверяй staged diff на секреты. Сборка без предупреждений и тесты обязательны перед PR/мержем согласно `docs/git-process.md`.
