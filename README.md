# Dobropay

Dobropay — платёжный шлюз на .NET 10 и Next.js с отдельной PostgreSQL для каждого сервиса. Архитектура, контракты и правила разработки описаны в [docs/README.md](docs/README.md) и [AGENTS.md](AGENTS.md).

## Состояние выпуска

Интерфейс кабинета работает с API без локальных подстановок. Настройка баз данных выполняет только миграции и не создаёт аккаунты, магазины, ключи или подписки. При `SANDBOX_ENABLED=false` сервис платежей не принимает изменяющие запросы и возвращает `503` на проверку готовности: реальные адаптеры эквайринга пока не реализованы. Такой контур нельзя включать для приёма денег.

Для запуска понадобится заполнить `.env` по [.env.example](.env.example) уникальными секретами, доменом, внешним SMTP и параметрами фискального провайдера. Пустые обязательные значения не проходят проверку Compose или запуск сервисов. Публичная регистрация сотрудника — `POST /v1/auth/register`; затем можно создать магазин через кабинет или `POST /v1/developer/shops`.

Публичные страницы: `/` — лендинг, `/managing` — кабинет магазина, `/developers` — документация API. Спецификация сервиса платежей доступна на `/swagger`.

Перед включением платёжных операций нужны интеграция с реальным провайдером карт/СБП, проверка его callback и возвратов, подтверждённый контракт облачной кассы, проверка работы SMTP и webhook, а также испытания на инфраструктуре выпуска. [Подробный список](docs/production-readiness.md).
